# 2026-08-16 — FA-27 in review: Ika heroes survive a leading nonce-advance

`extract_ika` never got the leading-`AdvanceNonceAccount` tolerance FA-09 gave
`extract_send`, so an Ika transaction rewritten with a durable-nonce advance
(FA-26, in flight on the extension) would drop from its zoned hero screen to
the generic instruction list — still signable, just unlabeled. Branch
`feat/ika-nonce-skip`, PR #133.

## Device (`core/`)
- `extract_ika` gained a `Some("System")` arm mirroring `extract_send`'s
  (FA-09) disc-4 skip: a leading `AdvanceNonceAccount` is tolerated and
  ignored (it moves no funds, identifies no msig state); any other System
  instruction still fails the tx back to the generic list.
- New fixture `hardware/testdata/examples/ika/tx_execute_with_nonce.bin`:
  `tx_execute` (the simplest Ika ix — disc 4, no payload) prefixed with
  `System::AdvanceNonceAccount`, generated by a new `execute_with_nonce_tx`
  helper in `gen-ika-fixtures`.
- New test `extract_zoned_lifts_ika_execute_past_leading_nonce_advance`
  confirms the `IkaExecute` hero still emerges and the leading instruction is
  labeled "Advance Nonce" (not the unknown-instruction warning path).
- `core/` tests: 346 passed (default features), 347 passed (`touch-ui`).
  `just check` (host `cargo check` + ARM cross-compile) green.

## Build (`justfile`)
- Fixed the stale `nonce-fixtures` recipe. It said `cd hardware`, a directory
  that hasn't held a crate since the `raspberry-pi` rename (`dde85ed`);
  running `cargo run --bin gen-nonce-fixtures` from there couldn't resolve a
  current package and fell back to building the whole workspace, including
  the ESP32-S3 target, which fails outside the ESP-IDF toolchain. Fix keeps
  the CWD at `hardware/` (so the generator's relative
  `testdata/examples/nonce/` output still lands where the parser's
  `include_bytes!` reads from) and adds `--manifest-path
  ../raspberry-pi/Cargo.toml` to scope cargo to the right crate. Verified:
  `just nonce-fixtures` now runs clean and reproduces the two committed
  fixtures byte-for-byte.
- Deviation from the plan: the plan said `cd hardware` → `cd raspberry-pi`.
  That literal change does make the recipe run, but it writes fixtures to
  `raspberry-pi/testdata/examples/nonce/` — a location nothing reads from —
  silently breaking the recipe's actual purpose. Kept `cd hardware` and fixed
  the real bug (package resolution) instead. `ika-fixtures` has the identical
  underlying bug but is out of scope for this card — flagged, not touched.
